### 1. 进程的本质与组成
#### ● 静态 vs 动态：
程序是静态指令的集合（例如 `.exe` 文件），而进程是程序的动态执行过程（从创建到终止的整个生命周期）。

#### ● 唯一标识：
进程通过 **进程 ID（PID）** 进行唯一标识，其核心标志是 **进程控制块（PCB）**，PCB 是进程存在的关键数据结构。

#### ● 核心组成（三部分）：
+ **程序段**：用于存放待执行的指令；
+ **数据段**：用于存放运行时的变量和数据；
+ **PCB（Process Control Block）**：记录进程的状态、资源占用情况、优先级等关键信息，是操作系统管理进程的核心数据结构。

### 进程的五大特征
1. **动态性**  
    - 进程具有从创建、运行、阻塞到终止的完整生命周期，而程序本身不具备生命周期。
2. **并发性**  
    - 多个进程可以在系统中交替执行，这种并发性通过 CPU 的时分复用技术实现。
3. **独立性**  
    - 每个进程拥有独立的资源空间（如内存、文件等），彼此之间互不干扰。
4. **异步性**  
    - 进程的执行速度无法预测，完全由调度算法决定，因此需要通过同步机制来协调进程间的协作。
5. **结构性**  
    - 进程的结构固定，由“程序段 + 数据段 + PCB（进程控制块）”三部分组成。

#### 如何实现原语的原子性？
通过关中断和开中断两个特权指令实现原子性。

和事务有点像，就是关中断执行后，不接收其他中断指令，只有等待指令执行完成之后，启动开中断才会进行其他指令。从而保证原子性。

### 调度算法
![画板](https://cdn.nlark.com/yuque/0/2025/jpeg/44165525/1759732978518-f162d2c2-9724-4eeb-b76f-076df7173f73.jpeg)

#### 1. 先来先服务（FCFS，First-Come, First-Served）
+ **原理**  
按照进程进入就绪队列的先后顺序进行调度，先进入队列的进程优先执行。
+ **优点**  
    - 实现简单。  
    - 公平性高，不会产生“饥饿”现象。
+ **缺点**  
    - 对短进程不友好，若长进程先到达，会导致短进程等待时间过长。  
    - CPU 利用率低。

#### 2. 短作业优先（SJF，Shortest Job First）
+ **原理**  
从就绪队列中选择预计运行时间最短的进程投入运行。
+ **优点**  
    - 平均周转时间和平均等待时间较短。  
    - 能有效提高系统吞吐量。
+ **缺点**  
    - 难以准确预知作业运行时间。  
    - 可能导致长作业“饥饿”，对长作业不公平。

#### 3. 最短剩余时间优先（SRTF，Shortest Remaining Time First）
+ **原理**  
它是 SJF 的抢占式版本，每当有新进程进入就绪队列且其剩余运行时间比当前正在执行进程的剩余时间更短时，就抢占当前进程的 CPU 资源。
+ **优点**  
    - 能及时响应短进程。  
    - 平均等待时间和周转时间较短。
+ **缺点**  
    - 需要不断计算剩余时间，系统开销较大。  
    - 同样存在长作业“饥饿”问题。

#### 4. 时间片轮转（RR，Round Robin）
+ **原理**  
将 CPU 时间划分为固定大小的时间片，就绪队列中的每个进程轮流运行一个时间片。若时间片用完进程未执行完，则将其放回就绪队列末尾，等待下一轮调度。
+ **优点**  
    - 能快速响应用户请求，适用于分时系统。  
    - 保证每个进程都能得到及时处理。
+ **缺点**  
    - 时间片设置过短会导致频繁的进程切换，增加系统开销。  
    - 时间片过长则退化为 FCFS。

#### 5. 优先级调度算法
+ **原理**  
为每个进程分配一个优先级，调度时选择优先级最高的进程执行。优先级可静态分配（创建进程时确定，运行中不变）或动态分配（根据进程的运行情况调整）。
+ **优点**  
    - 可根据进程的重要程度合理分配资源，例如保证关键系统进程优先执行。
+ **缺点**  
    - 若低优先级进程长期得不到调度，会产生“饥饿”现象。

#### 6. 多级反馈队列调度算法
+ **原理**  
设置多个优先级不同的就绪队列，每个队列对应不同的时间片（优先级越高，时间片越短）。新进程先进入最高优先级队列，按时间片轮转方式执行，若在一个时间片内未执行完，则降低优先级进入下一级队列，依此类推。
+ **优点**  
    - 结合了 FCFS、RR 和优先级调度算法的优点。  
    - 既能及时响应短进程，又能兼顾长进程。  
    - 还能保证优先级高的进程优先执行。
+ **缺点**  
    - 算法复杂度较高，需要合理设置队列数量、优先级和时间片大小。

#### <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">1）多级反馈队列调度（MLFQ）：平衡响应速度与公平性</font>
<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">MLFQ 是综合 “先来先服务（FCFS）、时间片轮转、优先级调度” 的经典算法，核心规则如下：</font>

1. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">队列结构</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：多个就绪队列，优先级从高到低（一级队列优先级最高），时间片从短到长（一级 10ms、二级 20ms、三级 40ms 等）；</font>
2. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">新进程入队</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：新进程先进入一级队列，按 FCFS 排队；</font>
3. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">时间片处理</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：若进程在当前队列时间片内未执行完，“下放” 到低一级队列末尾；</font>
4. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">调度顺序</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：高优先级队列空时，才调度低优先级队列（“先高后低”）；</font>
5. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">抢占性</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：低优先级进程运行时，若高优先级队列有新进程，立即抢占 CPU；</font>
6. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">避免饥饿</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：低优先级队列中等待过久的进程（如超过阈值），“升级” 到高优先级队列；</font>
7. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">短作业优势</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：短作业可在高优先级队列的时间片内完成，响应速度快；长作业逐渐下放，不会被饿死。</font>

#### <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">(2）多级队列调度：按进程类型分类调度</font>
+ **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">核心逻辑</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：按进程用途划分多个独立队列（如系统进程队列、交互式进程队列、批处理进程队列），每个队列采用不同调度策略：</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">系统进程队列（内存管理）：高优先级，抢占式调度；</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">交互式进程队列（游戏、打字）：中优先级，时间片轮转；</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">批处理进程队列（AI 训练）：低优先级，FCFS。</font>

#### <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">(3）多处理机调度（多核 CPU 场景）</font>
<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">核心目标：</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">负载均衡</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">（各 CPU 负载均匀）+</font><font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);"> </font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">处理机亲和性</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">（进程尽量在固定 CPU 执行，减少缓存失效）。实现方案：</font>

| **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">队列类型</font>** | **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">核心逻辑</font>** | **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">优点</font>** | **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">缺点</font>** |
| :--- | :--- | :--- | :--- |
| <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">公共就绪队列</font> | <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">所有 CPU 共享一个就绪队列，互斥访问</font> | <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">天然负载均衡</font> | <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">频繁切换 CPU，亲和性差</font> |
| <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">私有就绪队列</font> | <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">每个 CPU 有独立就绪队列，通过 “迁移策略” 平衡负载</font> | <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">亲和性好，切换成本低</font> | <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">需额外维护负载均衡</font> |


+ **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">迁移策略</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">Push 迁移：周期性检查各 CPU 负载，将繁忙 CPU 的任务 “推” 给空闲 CPU；</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">Pull 迁移：空闲 CPU 主动 “拉取” 繁忙 CPU 的任务。</font>

## 补充


1. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">虚拟内存与进程切换</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：每个进程有独立虚拟内存空间，操作系统需维护 “虚拟内存→物理内存” 映射表；进程切换时需同步切换映射表，这是进程切换成本高的核心原因之一。</font>
2. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">操作系统的核心作用</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：作为 “硬件与应用程序的中间层”，管理 CPU、内存、磁盘等硬件资源，合理分配给进程 / 线程，确保应用程序高效、稳定运行。</font>
3. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">原语与事务的类比</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：原语的原子性与数据库 “事务” 类似 —— 执行过程中不响应外部中断，确保操作连续、不可拆分（如创建原语需同时完成 PCB 初始化、资源分配、入队，缺一不可）。</font>
4. **<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">计算机核心资源</font>**<font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">：</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">处理资源：CPU、寄存器（程序计数器 PC、指令寄存器 IR 等，记录指令执行状态）；</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">存储资源：物理内存、物理磁盘；</font>
    - <font style="color:rgb(0, 0, 0);background-color:rgb(252, 252, 252);">通信资源：文件描述符、网络端口。</font>
