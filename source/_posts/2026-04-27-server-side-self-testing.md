作为服务端开发，具备自测能力是基础素养，能有效减少测试阶段的返工次数，大幅提升交付效率。

## 测试阶段

| 阶段 | 说明 |
|------|------|
| 单元测试 / Mock 测试 | 模拟数据库等依赖，对单个函数/方法进行验证 |
| 集成测试 | 多个模块协同工作，验证接口之间的交互 |
| 系统测试 | 由测试团队完成，覆盖完整业务流程 |
| 验收测试 | 由产品/策划验收，确认功能符合需求 |

## 测试方式

- **黑盒测试**：只关注输入与输出，不关注内部实现
- **白盒测试**：结合代码逻辑，编写单元测试、覆盖率测试
- **灰盒测试**：介于黑白盒之间，了解部分内部结构

## 测试内容

- 功能验证
- **边界值**：输入边界、数组越界、最大/最小值等
- 性能
- **异常处理**：空指针、超时、非法参数等
- 安全

当前阶段重点关注**边界测试**和**异常测试**，这是减少线上 Bug 的核心手段。在模块设计时，应参考已有模块，注重解耦与可扩展性。

## Go 语言测试实践

### 表格驱动测试

表格驱动测试是 Go 中最推荐的单元测试写法，一次定义多个用例，统一执行：

```go
func TestAdd(t *testing.T) {
    testCases := []struct {
        name string
        a    int
        b    int
        want int
    }{
        {"正数相加", 1, 2, 3},
        {"负数相加", -1, -1, -2},
        {"零相加", 0, 5, 5},
    }

    for _, tc := range testCases {
        t.Run(tc.name, func(t *testing.T) {
            got := Add(tc.a, tc.b)
            if got != tc.want {
                t.Errorf("预期:%d, 实际:%d", tc.want, got)
            }
        })
    }
}
```

### Mock 测试

适用于有外部依赖的场景，例如模拟邮件发送服务，使测试不依赖真实的第三方接口。

### 常用 testing 方法

| 方法 | 说明 |
|------|------|
| `t.Run()` | 创建子测试 |
| `t.Error()` | 记录错误，测试继续执行 |
| `t.Fatal()` | 记录错误，立即终止测试 |
| `t.Log()` | 记录调试日志 |
